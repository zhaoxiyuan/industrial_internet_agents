# 时间窗口与单票调度契约

Main 通过 bind_work_permit 登记用户票号、开始时间、人员/设备及依据。后台绑定唯一当前票；P6 无需选择候选票。configure_schedule 设置 window_seconds 与 max_parallel；一旦领取窗口，窗口长度锁定，防止重切导致重叠。按次调度和平台心跳共享进度，心跳 H 与窗口 N 独立。

list_time_windows 支持 limit（X条）、start_time（可选）、state。省略时间从作业范围内最早窗口开始，按开始时间升序；next_start_time 用于继续分页。返回连续完成时间、待处理数量、失败数量、运行数量和空闲并发位。查询不占用任务。

Main 按空闲位提交 P6 input={}，工具自动原子领取最早可用窗口；或按列表原值传 start_time。每个 run 只绑定一个窗口，同run重复读取不再领取；失败由Main按时间恢复，新run接管后旧run不能写入。超过三次失败停止自动恢复。

P6 read_current_window 获取当前票、时间范围、观察项、短整数观察序号及完整性；必要时 read_current_evidence 按观察序号核对原证据。save_current_description 恰好覆盖异常观察序号，正常和未知窗口同样保存，输入无作业ID、记录ID、租约token。一次事务写入窗口完成索引与一条P6_P7描述；重复同内容返回原回执，改内容拒绝。

并发允许后窗先保存，但P7领取前检查时间列表中最早未推进窗口。前窗未完成时返回明确时间阻塞，不把它当作真实采样断档。真实原始数据断档保留unknown，不证明风险恢复。

close_time_monitoring 只在用户明确结束监测时执行。省略cutoff表示工具使用当前作业范围内可用窗口末尾的完整精度；不是把用户要求的现在替换成旧数据末尾。指定时间须与窗口边界一致；未完成或在途窗口阻挡关闭。结束监测不自动完成处置、风险或人工终审。

旧的来源保存→候选票查询→归属补办流程已从Main/P6工具和运行实现删除。P7不再检查旧acquisition归属队列。历史业务保留历史数据和审计；新的工具包统一使用v5契约，真实平台验证不清库。

当前契约：单作业票、时间调度（v5）。Main 管票与时间进度，P6 每次读取一个原始窗口并原子保存一份 P6_P7 描述；P7 顺序研判；P8/P9 维护同一卡片并复核材料。播放器只作为原始关联事件数据源，新流程不调用播放器任务领取/完成接口。窗口 ID、租约、精确时间和幂等由工具内部维护。

结束监测后，目录以 monitoring_cutoff 截断，后续播放器数据不会扩大已结束范围；恢复监测后重新按原作业范围读取。
