# P3 作业上下文标准化

P3 把任务信息聚合为统一上下文包，供资源绑定、条件核验和后续风险分析使用。实现文件：`agents/p3_context_agent.py`。

## 流程

```text
p2_result.json.task_id
  → context_build
  → 聚合作业、区域、设备、介质、人员、资质、风险、措施、时间、关联作业、数据源
  → context_validate
  → 缺失字段触发人工确认
  → p3_result.json
```

## 数据结构

```json
{
  "job_id": "...",
  "stage": "P3",
  "context": {
    "task_id": "TASK-...",
    "job_type": "受限空间",
    "region": {},
    "equipment": [],
    "medium": [],
    "personnel": [],
    "qualifications": [],
    "risks": [],
    "measures": [],
    "time_window": {},
    "related_jobs": [],
    "sources": []
  },
  "missing_fields": [],
  "completed": true
}
```

每个外部字段应保留来源、获取时间和有效期；`missing_fields` 非空时增加 `pending_confirmation.type=context_missing`。

## 标准化接口（重要）

| 接口 | 说明 |
|---|---|
| `execute_stage(job_id: str) -> dict` | 读取 P2、构建上下文、写 `p3_result.json` |
| `context_build(task_id) -> str` | 构建 11 维上下文 |
| `context_validate(task_id) -> str` | 校验必填字段和一致性 |
| `context_history(task_id) -> str` | 查询上下文变更历史 |
| `run_context_agent(message) -> str` | 自然语言 Agent 入口 |

HITL 版中 `context_build`、`context_validate` 需要确认，历史查询自动执行。

## 集成约束

- 输入：`data/jobs/{job_id}/p2_result.json`。
- 输出：`data/jobs/{job_id}/p3_result.json`。
- 标准结果应传播 `task_id`。当前 `execute_stage` 主要把 task ID 放在 `context.task_id` 中，消费者应优先从 context 读取，并兼容顶层字段缺失。
- P4 不应依据自然语言重新推断设备或区域，应消费已标准化 context。
