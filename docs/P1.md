# P1 作业许可与 JSA

P1 读取作业申请，生成作业票草稿和 JSA 结果，并通过 HITL 完成最终审批。实现文件：`agents/p1_permit_agent.py`。

## 流程

```text
application.json
  → permit_submit
  → jsa_analyze
  → permit_generate_draft
  → 汇总 task_id、permit_draft_id、JSA、票证内容和缺失项
  → 工具级 HITL 或最终审批
  → p1_result.json
```

首次执行读取 `data/jobs/{job_id}/application.json.application`。Agent 工具调用中断时返回 `pending_confirmation`；恢复时复用同一 `job_id` 对应的 Agent/checkpoint。

## 数据结构

```json
{
  "job_id": "20260914123000123",
  "stage": "P1",
  "task_id": "TASK-20260914123000123",
  "permit_draft_id": "PD-20260914123000123",
  "jsa_result": {"hazards": [], "measures": []},
  "permit_content": {},
  "missing_fields": [],
  "completed": true,
  "completed_at": "ISO-8601 UTC",
  "pending_confirmation": {"type": "permit_final_approval", "message": "..."}
}
```

当 LLM 结果缺少必要字段时，P1 会根据 application 生成 fallback `task_id`、草稿 ID、JSA 和票证内容。

## 标准化接口（重要）

| 接口 | 输入 | 输出/副作用 |
|---|---|---|
| `execute_stage(job_id, resume=False, decision="approve", notes="") -> dict` | 作业 ID 和恢复决策 | 标准阶段结果；写 `p1_result.json` |
| `run_permit_agent(message) -> str` | 自然语言 | Agent 文本结果 |
| `run_permit_agent_with_hitl(message, thread_id, resume=False, decision="approve", notes="")` | 对话和 thread ID | `{interrupted,result,next}` |
| `is_agent_interrupted(thread_id) -> bool` | thread ID | 是否等待工具确认 |
| `get_agent_next_tools(thread_id) -> list` | thread ID | 待确认工具列表 |

LLM 工具：`permit_submit(application: str)`、`jsa_analyze(task_id)`、`permit_generate_draft(task_id)`、`permit_check(permit_id)`。工具返回 JSON 字符串，采用统一 `schema_version/command/result/errors` 或 `schema_version/error` envelope。

## HITL 与持久化

- P1 写操作通过 HumanInTheLoop middleware 管理；旧的工具级中断仍可恢复。
- `job_id` 同时作为工作流 thread ID 和持久化目录键。
- 结果文件：`data/jobs/{job_id}/p1_result.json`。
- 缺少 application 时返回 `completed=false`；不得进入 P2。

总流程和通用错误格式见 [系统架构](architecture.md) 与 [Human-in-the-loop](HUMAN_IN_THE_LOOP.md)。
