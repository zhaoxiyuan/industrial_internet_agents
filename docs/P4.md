# P4 监测资源绑定

P4 将摄像头、传感器和人员定位资源绑定到作业任务，并把无法自动匹配的资源交给人工处理。实现文件：`agents/p4_binding_agent.py`。

## 流程

```text
p3_result.json.context/task_id
  → binding_match
  → 生成 camera/sensor/location bindings
  → 记录 unmatched_resources
  → 人工确认或补充资源
  → p4_result.json
```

## 数据结构

```json
{
  "job_id": "...",
  "stage": "P4",
  "bindings": {
    "cameras": [],
    "sensors": [],
    "locations": []
  },
  "unmatched_resources": [],
  "completed": true,
  "pending_confirmation": {
    "type": "binding_confirm",
    "message": "请确认监测资源绑定是否正确"
  }
}
```

资源条目应包含资源 ID、类型、覆盖范围或点位、匹配依据和状态，避免只保存展示名称。

## 标准化接口（重要）

| 接口 | 说明 |
|---|---|
| `execute_stage(job_id: str) -> dict` | 读取 P3、完成匹配、写 `p4_result.json` |
| `binding_match(task_id) -> str` | 自动匹配资源 |
| `binding_status(task_id) -> str` | 查询绑定状态 |
| `binding_confirm(task_id) -> str` | 人工确认绑定 |
| `binding_request_manual(task_id, resource_type) -> str` | 请求补充指定类型资源 |
| `run_binding_agent(message) -> str` | 自然语言 Agent 入口 |

除 `binding_status` 外，HITL 版的绑定、确认和人工补充均需要确认。

## 匹配和集成约束

- 固定摄像头按区域覆盖匹配；传感器按区域和介质匹配；定位资源按人员工卡匹配。
- 输入：`data/jobs/{job_id}/p3_result.json`；输出：`p4_result.json`。
- 当前执行入口读取 P3 顶层 `task_id`，而 P3 可能只在 `context.task_id` 中保存它；集成方应兼容两处，后续代码应统一到顶层传播。
- `unmatched_resources` 非空不等于阶段异常，但必须在进入 P5 前人工确认。
