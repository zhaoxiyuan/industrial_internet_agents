# P6 作业过程动态监测

本文是 P6 的权威说明，以 `agents/p6_monitor_agent.py` 当前实现为准。P6 负责采集现场模拟数据、生成时序快照、调用 A5 识别候选事件，并在同一 FastAPI 服务中承载 P7/A6 路由。

## 1. 职责与边界

- 输入：`job_id`、监测场景、持续时间、轮询间隔、批大小。
- 处理：`AsyncCollector` 生成 CV、传感器、定位快照，`A5Agent` 批量分析快照。
- 输出：A5 `raw_event_*.json`、P6 `candidate_events`，并异步触发 P7 研判。
- 不负责：最终风险等级、处置决策、飞书通知。

P6 有两条入口，语义不同：

1. **实时监测入口**：`POST /api/monitor/start`，运行完整采集和分析流程。
2. **主工作流标准入口**：`execute_stage(job_id)`，满足 P1-P10 调度契约；当前通过 `monitor_start`、`monitor_events` 兼容工具生成阶段结果，不会启动完整 30 秒采集。

需要真实监测数据时应调用 HTTP 实时监测入口，不能把兼容工具当成实时采集接口。

## 2. 实时处理流程

```text
POST /api/monitor/start
  → 校验 17 位 job_id 和场景 A-E
  → 停止已有 active job（当前只允许一个活动作业）
  → 立即启动 A5Agent 轮询任务
  → 等待 play_delay_sec（默认 5 秒）
  → AsyncCollector 按秒生成 CV/传感器/定位数据和 snapshot
  → A5Agent 按 batch_size 读取 snapshot
  → 成功写 raw_event_*.json，失败写 error_*.json
  → 有事件时调用 P7.trigger_a6_assessment(..., job_id=...)
  → 查询 monitor/agent 状态与事件
```

状态保存在进程内 `_active_jobs[job_id]`：`starting → agent_running/playing → completed`，异常为 `error`，主动停止为 `cancelled`。

## 3. 数据结构

### 启动请求

```json
{
  "job_id": "20260914123000123",
  "scenario": "B",
  "duration_sec": 30,
  "interval_sec": 10,
  "batch_size": 10,
  "play_delay_sec": 5
}
```

P6 HTTP 接口中的 `job_id` 必须匹配 `^\d{17}$`；`scenario` 只能为 `A/B/C/D/E`。

### 候选事件

```json
{
  "event_type": "candidate_event",
  "event_id": "A5-...",
  "description": "未佩戴安全帽",
  "confidence": 0.9,
  "evidence": [{"source": "A5", "type": "PPE缺失", "person": {}}],
  "severity": "PENDING_A6",
  "timestamp": "2026-09-14T12:30:05+08:00",
  "type": "PPE缺失",
  "person": {"id": "P7", "name": "张师傅", "role": "焊工"}
}
```

`severity=PENDING_A6` 表示 P6 不做最终判级。

### 标准阶段结果

`execute_stage(job_id)` 写入 `data/jobs/{job_id}/p6_result.json`：

```json
{
  "job_id": "20260914123000123",
  "stage": "P6",
  "started_at": "ISO-8601 UTC",
  "session_id": "session_ab12cd34",
  "candidate_events": [],
  "completed": true,
  "completed_at": "ISO-8601 UTC"
}
```

失败时 `completed=false` 并增加 `error`。

### 持久化目录

```text
data/jobs/{job_id}/P6/
  cv_*.json
  sensor_*.json
  position_*.json
  snapshot_*.json
  processing_batch_*.json
  raw_event_*.json
  error_*.json
data/jobs/{job_id}/p6_result.json
```

## 4. 标准化接口（重要）

### Python 接口

| 接口 | 输入 | 输出/用途 |
|---|---|---|
| `execute_stage(job_id: str) -> dict` | 主流程作业 ID | P1-P10 调度唯一标准入口 |
| `run_a5_monitoring(job_id, work_permit, duration_sec=30) -> dict` | 作业、作业票、时长 | 完整异步监测结果 |
| `map_a5_events_to_p6(raw_events, job_id) -> list` | A5 原始事件 | 标准候选事件 |
| `get_p6_log_dir(job_id) -> str` | 作业 ID | `data/jobs/{job_id}/P6` |
| `monitor_start.invoke({"task_id": ...})` | P5 task ID | 兼容会话信息 |
| `monitor_events.invoke({"task_id": ...})` | P5 task ID | 兼容事件文本 |

### HTTP 核心接口

| 方法与路径 | 输入 | 成功结果 |
|---|---|---|
| `POST /api/monitor/start` | `MonitorStartRequest` | `status=ok`、P6/P7 目录、时长 |
| `POST /api/monitor/stop` | `{"job_id":"..."}` | 最终状态 |
| `GET /api/monitor/status?job_id=...` | 可选 job_id | 单作业或活动作业列表 |
| `GET /api/agent/status?job_id=...` | 可选 job_id | 批次统计和文件统计 |
| `GET /api/agent/events?job_id=...` | 可选 job_id | `raw_event` 聚合列表 |
| `GET /api/logs?job_id=...` | 可选 job_id | 按类型分组的日志文件 |
| `GET /api/logs/{path}?job_id=...` | 文件名、job_id | 单个 JSON 文件 |
| `POST /api/logs/clear` | `{"job_id":"..."}` | 删除数量；必须精确指定作业 |

`/api/scenario/*` 和 `/api/agent/*` 无 job_id 的调用是旧版全局调试模式；新集成应统一传 job_id。

## 5. 失败与并发约束

- 同时只允许一个 per-job 监测任务；新任务会停止旧任务。
- per-job 模式运行时，不允许再启动全局 Agent，避免两个 loop 竞争同一目录。
- 单个损坏的 `raw_event` 文件会被跳过；启动参数非法返回错误对象或 HTTP 400。
- P7 触发失败不会改写 P6 原始证据，排障时应同时检查 `P6/` 和 `P7/`。

跨阶段字段约定见 [P6-P8 标准接口契约](P6_P8_STANDARD_INTERFACES.md)。
