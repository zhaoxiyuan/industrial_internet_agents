# P10 归档与复盘

P10 将 P9 结果转为归档记录，并生成最终确认点。当前实现是轻量工作流入口，不包含独立 LLM Agent 或案例挖掘工具。实现文件：`agents/p10_archive_agent.py`。

## 流程

```text
p9_result.json
  → 读取 task_id；缺失时回退 job_id
  → 生成 archive_id 和归档内容清单
  → 标记 archived
  → pending_confirmation: report_confirm
  → p10_result.json
```

## 数据结构

```json
{
  "job_id": "20260914123000123",
  "stage": "P10",
  "task_id": "20260914123000123",
  "archive_result": {
    "task_id": "20260914123000123",
    "archive_id": "ARC-20260914123000",
    "archived_at": "ISO-8601 UTC",
    "contents": [
      "作业票证",
      "视频证据片段",
      "风险事件记录",
      "处置全记录",
      "作业报告"
    ],
    "status": "archived"
  },
  "completed": true,
  "pending_confirmation": {
    "type": "report_confirm",
    "message": "请确认归档报告"
  }
}
```

## 标准化接口（重要）

```python
def execute_stage(job_id: str) -> dict
```

这是当前 P10 唯一公共业务接口：读取 `data/jobs/{job_id}/p9_result.json`，写入 `p10_result.json`，并追加作业日志。

## 边界与约束

- `completed=true` 表示归档清单已生成，不代表归档文件已经打包或上传外部档案系统。
- 当前 `contents` 是声明性清单，代码没有逐项验证文件存在，也没有计算校验和。
- `archive_id` 使用秒级时间戳；高并发归档时可能重复，接入真实档案库前应增加 job_id 或随机后缀。
- `pending_confirmation` 要求人工确认报告，但当前 P10 模块本身不实现确认处理，确认由主调度器负责。
- 如需案例挖掘、性能分析、规则建议，应新增版本化接口，而不是假设旧文档中的 `archive_*` 工具仍存在。

## 持久化

- 输入：`data/jobs/{job_id}/p9_result.json`。
- 输出：`data/jobs/{job_id}/p10_result.json`。
- 日志：作业级 `logs.json`/统一 stage logger。

通用阶段契约见 [系统架构](architecture.md)。
