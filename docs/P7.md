# P7 风险研判与分级

本文是 P7 的权威说明，以 `agents/p7_risk_agent.py` 与 `A6/agent/a6_agent.py` 当前实现为准。P7 将 P6 候选事件交给 A6Agent，完成去重、聚合、风险分级和处置建议生成。

## 1. 职责与部署

- P7 不单独监听端口；`register_a6_routes()` 把 `/a6` 和 `/api/a6/*` 挂到 P6 的 FastAPI 应用（默认 5002）。
- P6 实时监测通过 `trigger_a6_assessment()` 在进程内调用 P7，避免 HTTP 自调用。
- 主工作流通过标准入口 `execute_stage(job_id)` 读取 `p6_result.json` 并逐条调用 `risk_analyze`。

## 2. 处理流程

### 实时链路

```text
P6 raw_event
  → trigger_a6_assessment(event_id, event_data, job_id)
  → get_a6_agent(job_id)
  → A6Agent.process_event
  → 按人员和违规类型去重、聚合 active violation
  → LLM/规则计算 1-5 级风险
  → data/jobs/{job_id}/P7/a6_*.json
```

### 主工作流链路

```text
execute_stage(job_id)
  → 读取 data/jobs/{job_id}/p6_result.json.candidate_events
  → 对每个 event_id 调 risk_analyze
  → 将工具 result 汇总为 risk_events
  → 写 data/jobs/{job_id}/p7_result.json
```

`risk_analyze` 是兼容工具，默认使用全局 A6Agent；实时 per-job 集成优先使用 `trigger_a6_assessment(..., job_id=...)`。

## 3. 数据结构

### A6 研判记录

```json
{
  "a6_event_id": "A6-...",
  "aggregated_from": ["A5-..."],
  "event_type": "PPE缺失",
  "first_seen": "ISO-8601",
  "last_seen": "ISO-8601",
  "wall_time": "ISO-8601",
  "duration_sec": 15,
  "involved_persons": ["P7"],
  "risk_level": 4,
  "risk_level_name": "严重",
  "risk_basis": "规则及证据依据",
  "suggestions": ["立即整改"],
  "reasoning": "研判过程摘要",
  "evidence": {},
  "timestamp": "ISO-8601"
}
```

风险映射：`1-2 → LOW`、`3 → MEDIUM`、`4 → HIGH`、`5 → CRITICAL`；`risk_level=0` 表示无风险，列表接口默认过滤。

### 标准阶段结果

```json
{
  "job_id": "20260914123000123",
  "stage": "P7",
  "started_at": "ISO-8601 UTC",
  "risk_events": [
    {
      "event_id": "A5-...",
      "level": "HIGH",
      "risk_level": 4,
      "risk_level_name": "严重",
      "risk_basis": "...",
      "suggestions": [],
      "a6_event_id": "A6-...",
      "raw_result": {}
    }
  ],
  "completed": true,
  "completed_at": "ISO-8601 UTC"
}
```

单条研判失败会记录 warning 并继续其他事件；阶段读取或写入失败时返回 `completed=false` 和 `error`。

## 4. 标准化接口（重要）

### Python 与工具接口

| 接口 | 输入 | 输出/用途 |
|---|---|---|
| `execute_stage(job_id: str) -> dict` | 作业 ID | P1-P10 调度唯一标准入口 |
| `trigger_a6_assessment(event_id, event_data, *, job_id="")` | A5 事件 | 实时异步研判；应传 job_id |
| `risk_analyze.invoke({"event_id": ...})` | P6 event ID | JSON 字符串，含标准化 `level` |
| `risk_list.invoke({"task_id": ...})` | task ID | 最多 50 条全局历史事件 |
| `get_a6_agent(job_id)` | 作业 ID | per-job A6Agent |
| `clear_a6_agent(job_id)` | 作业 ID | 清理进程内 Agent 缓存 |
| `register_a6_routes(app, ...)` | FastAPI app | 注册 P7 Web 接口 |

工具成功响应核心形态为 `{"status":"...","result":{...}}`；工具捕获异常后返回 `status=error`，不会向调用者抛出业务异常。

### HTTP 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /a6` | 风险研判看板 |
| `GET /api/a6/assessments?job_id=...&risk_level=...&limit=...` | 研判列表 |
| `GET /api/a6/assessments/{a6_event_id}?job_id=...` | 单条详情 |
| `GET /api/a6/status` | 事件映射与汇总状态 |
| `POST /api/a6/process/{event_id}` | 外部手动触发；body 可含 `job_id` 和事件数据 |
| `GET /api/a6/prompts` | 列出提示词 |
| `GET/POST /api/a6/prompts/{name}` | 读取或更新内存提示词 |
| `POST /api/a6/prompts/{name}/save` | 写回提示词文件 |
| `POST /api/a6/prompts/{name}/reset` | 恢复默认提示词 |
| `POST /api/a6/clear_logs` | 清空指定 `job_id` 的 P7 目录；job_id 必填 |

## 5. 持久化和约束

```text
data/jobs/{job_id}/P7/a6_*.json   # 实时 per-job 真相数据
data/jobs/{job_id}/p7_result.json # 主工作流聚合结果
A6/logs/assessments/YYYYMMDD/     # 不传 job_id 的兼容全局数据
```

- 新代码应始终传 job_id，避免数据落入全局兼容目录。
- P8 读取时会合并 `p7_result.json` 和 `P7/a6_*.json`；调用方需要按 `event_id/a6_event_id` 避免重复语义。
- `risk_level` 是 1-5 数字等级，`level` 是跨阶段标准枚举，两者不要混用。

跨阶段字段约定见 [P6-P8 标准接口契约](P6_P8_STANDARD_INTERFACES.md)。
