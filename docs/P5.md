# P5 开工前条件核验

P5 在进入动态监测前核验安全措施，并给出是否允许开工的建议。实现文件：`agents/p5_verify_agent.py`。

## 流程

```text
p4_result.json.task_id/bindings
  → verify_checklist
  → verify_execute
  → verify_recommendation
  → 人工确认核验结果
  → p5_result.json
```

核验范围包括隔离、警戒标识、消防器材、气体检测、人员资质和 PPE。

## 数据结构

```json
{
  "job_id": "...",
  "stage": "P5",
  "verification_result": {
    "task_id": "TASK-...",
    "items": [{"item": "气体检测", "result": "PASS", "evidence": []}]
  },
  "recommendation": {
    "decision": "ALLOW",
    "reasons": []
  },
  "completed": true,
  "pending_confirmation": {
    "type": "verification_approve",
    "decision": "ALLOW",
    "message": "请确认开工条件核验结果"
  }
}
```

检查项结果为 `PASS/PENDING/FAIL/N/A`；开工建议不能替代人工授权。

## 标准化接口（重要）

| 接口 | 说明 |
|---|---|
| `execute_stage(job_id: str) -> dict` | 执行核验和建议，写 `p5_result.json` |
| `verify_checklist(task_id) -> str` | 生成核验清单 |
| `verify_execute(task_id, checklist_id=None) -> str` | 执行核验 |
| `verify_recommendation(task_id) -> str` | 生成开工建议 |
| `run_verify_agent(message) -> str` | 自然语言 Agent 入口 |

HITL 版中清单查询自动执行，实际核验和开工建议需要确认。

## 集成约束

- 输入：`data/jobs/{job_id}/p4_result.json`；输出：`p5_result.json`。
- P6 标准入口读取 P5 的 `task_id`；因此 P5 结果应保留 task_id。当前部分链路可能没有顶层传播，调用方必须以 job_id 作为主关联键并兼容空 task_id。
- 任一强制项为 `FAIL` 时，不得将 recommendation 标为允许开工。
