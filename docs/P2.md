# P2 作业任务实例化

P2 根据 P1 的作业票草稿创建唯一任务实例，并询问是否纳入智能监测。实现文件：`agents/p2_task_agent.py`。

## 流程

```text
p1_result.json.permit_draft_id
  → task_instance_create（按 permit_id 幂等）
  → 得到 task_instance 和 task_id
  → pending_confirmation: monitor_decide
  → p2_result.json
```

## 数据结构

```json
{
  "job_id": "...",
  "stage": "P2",
  "task_instance": {
    "task_id": "TASK-...",
    "permit_id": "PD-...",
    "status": "created",
    "idempotent": false
  },
  "task_id": "TASK-...",
  "completed": true,
  "pending_confirmation": {
    "type": "monitor_decide",
    "message": "是否将此作业纳入智能监测"
  }
}
```

## 标准化接口（重要）

| 接口 | 说明 |
|---|---|
| `execute_stage(job_id: str) -> dict` | 读取 P1、创建实例、写 `p2_result.json` |
| `task_list(region=None, status=None) -> str` | 查询任务列表 |
| `task_get(task_id) -> str` | 查询任务详情 |
| `task_instance_create(permit_id) -> str` | 幂等创建任务 |
| `task_subscribe(task_id) -> str` | 建立任务变更订阅 |
| `run_task_agent(message) -> str` | 自然语言 Agent 入口 |

HITL 版中仅 `task_instance_create` 需要人工确认，其余为只读或订阅操作。工具返回标准 JSON envelope。

## 持久化与约束

- 输入：`data/jobs/{job_id}/p1_result.json`。
- 输出：`data/jobs/{job_id}/p2_result.json`。
- 同一 `permit_id` 重复创建必须返回同一任务或明确的 `idempotent=true`。
- `permit_draft_id` 为空时不应产生有效任务实例。

下一阶段 P3 依赖 `task_id`。
