# P9 闭环跟踪与报告

P9 汇总处置状态、校验闭环完整性、生成报告，并请求人工确认是否关闭事件和作业。实现文件：`agents/p9_closure_agent.py`。

## 流程

```text
p8_result.json
  → closure_status
  → closure_verify
  → closure_report
  → pending_confirmation: closure_close
  → 人工确认后 closure_close
  → p9_result.json
```

## 数据结构

```json
{
  "job_id": "...",
  "stage": "P9",
  "closure_status": {"status": "in_progress", "items": []},
  "verify_result": {
    "records_complete": true,
    "evidence_complete": true,
    "signatures_valid": true,
    "timeline_continuous": true
  },
  "report": {"format": "markdown", "path": "..."},
  "completed": true,
  "pending_confirmation": {
    "type": "closure_close",
    "message": "请确认是否关闭事件和作业"
  }
}
```

闭环完整性至少覆盖处置记录、证据、复核签字和时间线。

## 标准化接口（重要）

| 接口 | 说明 |
|---|---|
| `execute_stage(job_id: str) -> dict` | 读取 P8、生成闭环结果、写 `p9_result.json` |
| `closure_status(task_id) -> str` | 查询当前闭环状态 |
| `closure_verify(task_id) -> str` | 执行完整性检查 |
| `closure_report(task_id, format="markdown") -> str` | 生成过程报告 |
| `closure_close(task_id) -> str` | 关闭事件和作业 |
| `run_closure_agent(message) -> str` | 自然语言 Agent 入口 |

HITL 版中只有状态查询自动执行；验证、报告生成和关闭均需人工确认。

## 集成约束

- 输入：`data/jobs/{job_id}/p8_result.json`；输出：`p9_result.json`。P8 应在该结果中汇总 P9 需要的处置状态，P9 当前不会直接扫描 `P8/archived.json`。
- 当前 `execute_stage` 从 P8 顶层读取 `task_id`，但 P8 标准结果可能没有该字段。调用方应以 job_id 回退；后续实现应统一传播 task_id。
- `completed=true` 表示报告准备完成，不表示作业已经关闭；关闭必须经过 `closure_close`。
- 报告应引用证据路径或 ID，不应复制大体量视频或原始日志。
