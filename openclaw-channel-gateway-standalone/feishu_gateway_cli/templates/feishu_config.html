② 飞书 App 凭据（多账户）FEISHU_ACCOUNTS

Channel Gateway 支持同一进程内路由多个飞书 App,每个账户对应一个 account_id(URL 路径 /webhooks/feishu/<accountId>)。 account_id 必填且唯一,规则 ^[a-zA-Z][a-zA-Z0-9_-]*$。 description 仅 UI 注释用,不写入 gateway 配置。 敏感字段(APP_SECRET / VERIFICATION_TOKEN)UI 显示为 ***。

📋 添加完账户后,还需要去飞书开发者后台配置回调 URL（点击折叠）
  1. 打开 飞书开放平台 → 选相应 App（用本账户的 app_id 标识）
  2. 左侧导航 → 事件与回调 → 事件订阅
  3. 订阅方式选 「将回调发送至开发者服务器」（推荐）
  4. 请求地址填： 
    https://<你的公网IP或域名>/webhooks/feishu/<account_id>
    <account_id> 须与本表 account_id 主键完全一致； 公网 IP 推荐用 ngrok / frp / 域名 等内网穿透工具
  5. 点「保存」→ 飞书立即发 url_verification → 你的 Gateway 收到并返回 challenge → 红框「Challenge code没有返回」消失
  6. 启用后,到 权限管理 开通 Bot 需要的权限（im:message、im:message:send_as_bot 等）

💡 url_verification 失败常见原因： (1) Gateway 没启动 / 公网穿透掉线 → 访问 https://<你的公网IP>/healthz 应返回 {"status":"ok"} (2) URL 路径末尾的 account_id 与 config.feishu.local.json 中 accounts 块的 key 不一致 (3) verificationToken 与飞书开发者后台不一致

③ 飞书群聊（FEISHU_GROUP_MAP）

主键：chat_id（飞书群 ID）。每条群聊三字段： name（必填，发送时反查用）、description（可选，描述）。 同一 chat_id 被多个收件人共享时，名称/描述只需配一次。 （name 为空 = 占位条目标记，提示未命名）

chat_id (主键) name (必填) description (可选) 操作
④ 飞书收件人（FEISHU_USER_MAP）

主键：open_id（飞书用户唯一 ID）。每个收件人三字段： open_id（主键）、role（责任岗位）、name（中文姓名）。 同一 role 可对应多人 → P8 推送时群发。
群聊推送请到 ③ 配 FEISHU_GROUP_MAP，再单聊 open_id 用 send_to_group(group_name=...)； USER_MAP 仅负责"人"的索引。

open_id (主键) role (责任岗位) name (中文姓名) 操作
