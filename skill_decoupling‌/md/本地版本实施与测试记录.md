# 本地版本实施与测试记录

日期：2026-10-10。实施范围仅为 `skill_decoupling‌/`。本目录名称末尾有 U+200C 字符，建议用终端目录补全或资源管理器进入，不要手工猜测路径。

## 1. 本轮需求优先级

此前设计方案包含 Docker 服务包和保留 LangChain/LangGraph。根据用户后续要求，本轮调整为：

- 创建可独立复制的完整本地项目，仅使用 Python 标准库和浏览器原生前端。
- Skill 不带 Docker、MCP 地址、token 或启动服务声明；由标准 SKILL.md 和资源组成。
- 飞书配置页面写入独立 env；收发、回复、事件查询与 ACK 通过内置 HTTP MCP 发布。
- MCP 独立管理外部 HTTP 服务或本地 Python 服务，Docker 管理暂不提供。
- 边缘 Agent 部署只预留明确未实现的接口，返回 501。
- 注释覆盖所有 Python 模块、类、函数、方法、测试；前端具名函数和各事件处理组、CSS 布局也有中文说明。不是只注释关键模块。

## 2. 已实现

| 功能 | 结果 |
|---|---|
| 标准 Skill 校验和导入 | 目录或 ZIP，安全 frontmatter 子集、文件清单、路径限制和内容摘要去重 |
| Skill 资源 | 按需通过 MCP 读取文本，不自动执行 scripts |
| 标准功能库 | 飞书已实现；文件访问 reserved |
| 飞书配置 | 多连接配置页、原子 env 写入、旧值备份、敏感空值保留、不回显密钥 |
| 飞书消息 | 目录解析、只读连通测试、发送、入站签名/Token/解密、去重、回复、ACK |
| 飞书结果 | sent/failed/unknown；持久幂等回执，无自动写操作重试 |
| MCP 定义 | 外部地址、来源链接、token 引用、本地脚本入口/上传、工具目录、契约修订 |
| MCP 进程管理 | 显式启动/停止、协议就绪检查、占用端口拒绝、独立日志与数据目录 |
| Agent | 可先创建后配置模型，标准工具消息循环、Skill 按需加载、能力绑定、会话与审计 |
| 授权 | 工具白名单、连接绑定、目标范围、执行前复核、契约修订变化阻止旧绑定 |
| 后台操作 | 耗时工作异步受理，资源并发冲突为 409，页面查询不等待远程调用 |

模型运行时使用标准库的 OpenAI 兼容 tool_calls 适配器。实际模型 API 和飞书 API 属于可配置的业务连接，不是本地项目启动的必需外围服务。

## 3. 自动化验证

执行命令：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q app.py platform_core examples tests
node --check web/app.js
```

结果：**23 项测试通过，Python 编译及 JavaScript 语法检查通过。** 其中集成测试通过真实平台 HTTP 和真实 MCP 请求执行，模拟服务仅替代飞书/模型上游；本地 MCP 使用真实子进程。

覆盖：Skill 重复导入和 ZIP 路径越界；env 保留与密钥脱敏；MCP token；嵌套 Schema、本地引用、布尔/数字枚举区分、外部引用拒绝；发送幂等和未知结果；事件去重、签名、回复与 ACK；慢后台任务时 health/overview 响应；Agent→按需 Skill→MCP→飞书链路；授权撤销和目标范围；外部契约修订；本地进程启停和端口冲突；2026 请求元数据；Host/Origin 与私有文件访问限制；AES256 CBC NIST 向量。

第一次 HTTP 测试在受限沙箱中报 WinError 10013，原因为 loopback 连接被禁止。随后在允许本机连接的环境中完整运行通过；没有把沙箱错误算成应用测试通过。

## 4. 浏览器验收

通过本地管理页实际点击验证：

1. 导入自带飞书说明 Skill，提示未启动任何服务。
2. 不配置模型也能创建 Agent，消除“先创建才能保存、又无创建入口”的循环。
3. 保存本地 MCP 定义不会启动；明确点击启动后显示 running 并发现 echo/save_note。
4. Agent 页面可独立选择本地 MCP 能力来源，显示该服务工具。
5. 停止本地 MCP 后显示 stopped，平台仍在线可继续访问。

验收中修复了新建保存后继续保存会重复创建的前端状态问题，并补齐 MCP 定义编辑入口；同时修复 hidden 控件被 label 布局规则覆盖的问题。

当前管理页：`http://127.0.0.1:8770/`。保留自带 Skill、本地示例 Agent 和已停止的回声 MCP 定义，便于继续操作；没有保存真实飞书或模型凭据。

## 5. 明确未验收和未实现

- 没有发送真实飞书消息、验证真实机器人发消息权限、配置公网 Webhook 或实际模型账号。
- 真实收件需要可达的 HTTPS Webhook，仅转发回调路径；本项目没有改动旧项目 Nginx、ngrok、Mac 或 Docker。
- 入站消息当前持久化后由页面或工具读取，不自动驱动 Agent 回复。
- Docker、本地 stdio MCP、OAuth 自动授权、长期 SSE 订阅、MRTR、完整 JSON Schema/YAML 解析不在当前实现范围，详情见 README。
- 本地上传的 Python 代码以平台用户权限运行；没有额外 OS 沙箱。
- 边缘部署和通用文件功能仅预留位置。

运行方式、数据路径和模块关系详见 `README.md`。

## 6. 后续范围修订：移除 Python 部署

按用户要求，MCP 管理仅接入已运行的 HTTP/HTTPS 服务。Python 入口、脚本上传、参数、启停与日志管理接口已移除；旧定义转为 HTTP 接入并要求重新检查。Docker/K8s 部署在独立模块待开发。上文有关平台管理本地子进程的内容仅记录初版行为，不再适用于当前版本。

移除后的完整回归：27 项全部通过。浏览器确认无 Python 入口、上传、参数或启停控件。新增验证覆盖旧定义迁移、旧部署字段拒绝、本机 HTTP 服务发现和移除的启停 API；同时修复 Windows 下拒绝带 body 请求时的连接复位问题。

## 2026-10-10：统一 CLI 与本地多智能体协作实施

本次按《多智能体协同开发思路》改造，覆盖之前“内置功能经 HTTP MCP 发布”的实现记录；旧章节仅表示历史版本。

- 新增真实 CLI 入口及一次性参数绑定票据；平台内置飞书和 Skill 读取移除内部 MCP 调用，旧 /mcp 返回 404。
- 外部 HTTP MCP 保留，通过 CLI 适配；新增固定 GET/POST HTTP 直连契约、绑定与前端配置。
- 固定 Agent 新增职责、输入输出契约、并发、超时与版本；有方向协作授权单独管理，不允许模型创建 Agent。
- 新增 SQLite 协作任务大表、依赖、私有检查点、状态事件与任务成果下载。
- Runtime 与调度分离：父任务等待时释放线程，子任务完成后恢复；结果按契约校验，依赖成果实际传给后续执行者。
- 新增协作授权与任务总览前端；飞书入站可选绑定已定义 Agent，异步触发且按事件去重，默认保持仅接收。
- 模块分工见 README；不引入 Redis、LangChain 或外部运行服务，不建立当前版本备份。
- 当前仅单环境执行；分布式、Docker/Kubernetes 与边缘下发保留待开发标志。
- 重启未完成任务明确标记 interrupted，不自动重放可能产生副作用的动作；等待恢复指同进程协作检查点恢复。

验证使用 loopback 模拟模型、飞书、MCP 和真实 CLI 进程，不发送任何公网消息。测试覆盖原有功能回归及等待释放、依赖交付、权限隔离、配置版本、取消、超时、重启、两条外部调用路径和可选入站触发。具体执行结果以 tests 与 .runtime/all-collaboration-tests.txt 为准。

完整测试结果：42 项通过，耗时约 49 秒；Python 编译与两份 JavaScript 语法检查通过。

最终管理员 CLI 成功调用与审计专项检查通过；浏览器检查 Agent 契约、协作任务和 HTTP 直连页面无控制台错误。页面截图：多智能体协作页面.png。
